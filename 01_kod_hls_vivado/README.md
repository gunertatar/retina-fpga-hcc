# Profiling-Guided FPGA Acceleration of Retinal Vessel Segmentation

Code, bitstreams, trained weights and raw measurements accompanying

> G. Tatar, *Profiling-Guided FPGA Acceleration of Retinal Vessel Segmentation: HLS-Based Selective
> Offloading and Input-Channel Tiling on Zynq SoC Platforms*, High-Confidence Computing, Elsevier, 2026
> (accepted for publication).

The repository contains everything needed to reproduce the tables and figures of the paper: the
per-stage profiles, the partition design-space exploration, the two HLS cores and the Vivado block
designs, the bit-accurate verification of the cores on both boards, the DRIVE/STARE/CHASE_DB1/HRF
accuracy results with paired statistics, the fixed-point and tiling sensitivity analysis, and the
latency and power measurements on the PYNQ-Z1 and the Kria KV260.

## Contents

| Folder | Content |
|---|---|
| `model/` | LightUNet definition (`model.py`), training (`train.py`) and patch dataset (`dataset.py`) |
| `weights/` | Trained weights: `best_model.pth` (FP32, DRIVE; its enc1 is the ROM of both bitstreams), `hwaware_ps_DRIVE.pth` (PS layers fine-tuned with the bit-accurate PL front-end), `fp32_*.pth` / `hw_*.pth` (STARE, CHASE_DB1, HRF) |
| `hls/` | Vitis HLS 2022.1 sources of `preprocess_ip` and `conv_ip` (int16 output; `ICH_TILE` = 32 for the KV260 and 8 for the PYNQ-Z1), ROM header with the deployed weights (`conv_ip.h`, generated by `gen_weights.py`), C-simulation test bench (`tb.cpp`) |
| `hls/sweep/` | `ICH_TILE` sweep: generated sources (`src_<URAM>_T<ICH_TILE>.cpp`), run script, and the C-synthesis report of every point |
| `vivado/` | Block-design scripts of both deployed designs (`pynqz1_block_design.tcl`, `kv260_block_design.tcl`, written with `write_bd_tcl`) and the post-implementation reports (hierarchical utilization, timing, clocks, power) |
| `bitstreams/` | Deployed bitstreams and hardware hand-off files: PYNQ-Z1 (`retina_system_wrapper`) and KV260 (`retina_kv260_system_wrapper`) |
| `emulator/` | Bit-accurate model of both HLS cores (`hwemu.py`, NumPy; `common.py`, PyTorch) and the full-image evaluation pipeline |
| `experiments/` | Scripts for every experiment of the paper (see below) |
| `board/` | On-board measurement program (`board_run.py`), reference PS implementation (`ps_numpy.py`), C/NEON GEMM (`gemm.c`), power-phase runner (`pz_phase.py`); `kv260_petalinux/` contains a PYNQ-free AXI DMA driver (`/dev/mem` + dma-heap) and the device-tree overlay used on the KV260 PetaLinux image |
| `results/` | All numerical results (JSON) and the raw board outputs and logs (`board_raw/kv260`, `board_raw/pynqz1`, `pynqz1_power_usbmeter`) |

## Datasets

The datasets are public and must be obtained from their providers: DRIVE (Staal et al., 2004),
STARE (Hoover et al., 2000), CHASE_DB1 (Fraz et al., 2012), HRF (Budai et al., 2013). The
train/test splits follow Seo et al. (arXiv:2501.18921). Expected layout (run all scripts from the
repository root):

```
datasets/DRIVE-digital-retinal-images-for-vessel-extraction/{train,val}/{input,label}
datasets/DRIVE_official/test/mask/           # official DRIVE FOV masks
datasets/STARE-structured-analysis-of-the-retina/{train,val}/{input,label}
datasets/CHASE_DB1-retinal-dataset/{train,val}/{input,label}
datasets/HRF-high-resolution-fundus/{train,val}/{input,label}
```

## Reproducing the results

Host: Python 3.8+, PyTorch 2.x (CUDA optional), NumPy, SciPy, scikit-learn, Pillow, Matplotlib.
Hardware tools: Vitis HLS / Vivado 2022.1. Boards: PYNQ-Z1 (PYNQ image) and Kria KV260 (PetaLinux).

| Paper item | Command |
|---|---|
| Tables 2, 12 (DRIVE accuracy) | `python experiments/eval_acc.py DRIVE weights/best_model.pth base`, `python experiments/eval_acc.py DRIVE weights/hwaware_ps_DRIVE.pth hwaware` |
| Table 13 (paired statistics) | `python experiments/stats.py` |
| Table 3, Fig. 2 (per-stage profiles) | GPU: `python experiments/profile_gpu.py`; ARM: on the board, `python3 board/board_run.py <board> latency` |
| Table 6 (partition exploration) | `python experiments/dse.py` |
| Tables 7, 9; Fig. 4 (implementation) | `vivado/*_util*.rpt`, `vivado/*_timing.rpt`, `vivado/*_clocks.rpt`; block designs in `vivado/*_block_design.tcl` |
| Table 8 (AXI DMA configuration) | `vivado/*_block_design.tcl` (`c_sg_length_width`) |
| Section 6.4 (bit-accurate verification) | on the board: `board_run.py <board> validate`; then `python experiments/check_board.py <kv260\|pynqz1>` |
| Tables 10, 11 (latency, power, KV260) | on the board: `python3 board/board_run.py kv260 latency` / `power` |
| Table 11 (PYNQ-Z1 power) | on the board: `python3 board/pz_phase.py <idle\|pl\|ps\|full> <seconds>` with an external USB power meter; see `results/pynqz1_power_usbmeter/` |
| Table 14, Fig. 5a (precision sensitivity) | `python experiments/sweep_precision.py` |
| Table 15, Fig. 5b (`ICH_TILE` sweep) | `bash hls/sweep.sh` (Vitis HLS), then `python experiments/parse_hls.py`; the reports in `hls/sweep/` are those of the paper |
| Table 16 (additional datasets) | `python experiments/finetune_hw.py <DS> 40`, `python experiments/eval_ds.py <DS> ...` |
| Hardware-aware fine-tuning | `python experiments/finetune_hw.py DRIVE 40` |
| Section 7.3 (complexity) | `python experiments/complexity.py` |

The raw board outputs of the verification runs are included (`results/board_raw/<board>/validate_out_part1.npz`
and `_part2.npz`, patches 1-100 and 101-200 of the 200 DRIVE test patches, 26,214,400 values per board);
`check_board.py` reproduces `check.json` from them without a board.

## Rebuilding the hardware

1. Synthesise and export the two HLS cores with Vitis HLS 2022.1 as IP-catalog cores (`hls/preprocess.cpp`,
   and `hls/conv_ip_kv260_ICH32.cpp` or `hls/conv_ip_pynq_ICH8.cpp`).
2. In Vivado 2022.1, add the exported cores to the IP repository of a project for the corresponding part and
   run `source vivado/<board>_block_design.tcl`; then generate the HDL wrapper and the bitstream.

## Notes

* Both bitstreams contain the enc1 weights of `weights/best_model.pth`; the ROM contents were checked
  against the Vivado memory-initialisation files.
* `hls/conv_ip_kv260_ICH32.cpp` is functionally identical (bit-exact in C simulation and on the board)
  to the source from which the deployed KV260 core was synthesised; the latter pipelines the tap loop
  with the 32 channel products fully unrolled.
* On the KV260 the MM2S/S2MM channels of the two DMA engines are paired crosswise
  (`preprocess_ip`: MM2S of `axi_dma_0`, S2MM of `axi_dma_1`; `conv_ip`: the opposite);
  `board/kv260_petalinux/kvdma.py` handles this.
* The KV260 PL clock is set to 250 MHz (IOPLL/6) by `board/kv260_petalinux/load.sh`.
